# Data Sources

## Golden rules

1. **Free and public only.** No paid APIs, no scraping behind logins, no violating terms of service.
2. **Verify empirically before building.** Endpoints/limits below are best-known as of July 2026 — check the provider's docs if something stops working.
3. **Attribute everything.** Every module shows its data source and notes that quotes may be delayed. Footer states this project is independent and unaffiliated with any company, exchange, or data provider mentioned on the site.
4. **API keys stay server-side only.** Never expose a data-provider API key to the browser. In this codebase, only `src/lib/marketData.ts` reads `process.env.TWELVE_DATA_API_KEY` — client components go through the `/api/search` proxy route instead of calling the provider directly.

## Company Profile Generator — Twelve Data

- **Provider:** [twelvedata.com](https://twelvedata.com) — chosen over Finnhub because Finnhub's free tier blocks historical price candles (a 403 on that endpoint).
- **Free tier limits:** 800 requests/day, 8 requests/minute. No credit card required to sign up.
- **Correction (2026-07-20):** Twelve Data's docs make it look like `/profile` and `/statistics` (company description, P/E, market cap, dividend yield, margins, beta, etc.) are included free — they are not. Testing the real key showed both return HTTP 403 on the free Basic plan; they require the paid "Grow" plan ($29/month) or higher. This module was reworked to not depend on them at all — see `docs/DECISIONS.md`.
- **Endpoints used** (see `src/lib/marketData.ts`), all confirmed free on the Basic plan:
  - `/quote` — current price, day's change, day's open/high/low, previous close, volume, average volume, and 52-week high/low. Cached 60 seconds.
  - `/time_series` (interval=1day) — historical daily closes for the price chart, and the input to our own computed analytics (50-day moving average, annualized volatility — see `src/lib/profileAnalysis.ts`). Cached 15 minutes.
  - `/symbol_search` — ticker/name autocomplete, proxied through `/api/search` so the key never reaches the browser. Cached 1 hour.
- **Not used (paid-only on Twelve Data's free plan):** `/profile` (company description, sector, CEO, employees), `/statistics` (market cap, P/E, dividend yield, EPS, shares outstanding, beta). If real fundamentals data becomes important later, either upgrade the Twelve Data key or bring in a second, still-free source for that specific data — don't silently show broken/blank fields.
- **Correction (2026-07-20):** `/quote` and `/time_series` are only genuinely free for stocks whose **primary listing is a US exchange** (NYSE/NASDAQ), plus US OTC pink sheets. Confirmed empirically: `symbol_search` happily returns matches on foreign exchanges (LSE, ASX, TSX, Frankfurt, etc. — e.g. Diploma plc / `DPLM` on LSE, Woolworths Group / `WOW` on ASX, Unilever / `ULVR` on LSE), but calling `/quote` or `/time_series` for those symbols/exchanges returns HTTP 404 with `"available starting with the Grow/Pro/Venture plan"` — even for household names, and regardless of company size. Well-known UK/international names that *do* work (Shell, AstraZeneca, GSK, Rio Tinto) only work because Twelve Data resolves their ticker to a **US-listed ADR** (NYSE/NASDAQ) by default, not their home-exchange listing. A pure OTC pink-sheet ADR (e.g. `DPLMF` for Diploma) does technically return quote data on the free plan, but it's thinly traded and often stale (flat price, zero volume for days) — not accurate enough to show as "the price," so this isn't used as a silent substitute.
- **What this means in practice:** any company whose only listing is a foreign exchange, with no US ADR, cannot show real price data through Twelve Data without upgrading the plan — with one exception, Hong Kong, which this site now covers through a second free provider instead (see the EODHD section right below). The company page detects the Twelve Data plan-gate error and tells the user plainly why (see `src/app/profile/[symbol]/page.tsx`), and the search dropdown flags likely-unavailable exchanges up front (`src/components/profile/TickerSearch.tsx`) rather than letting them click through to a dead end.
- **Data freshness:** free-tier quotes are effectively real-time to slightly delayed depending on exchange — not tick-by-tick like a real Bloomberg terminal, but current enough to feel live for a student tool. This is stated in the module's UI.
- **Getting a key:** sign up free at [twelvedata.com/pricing](https://twelvedata.com/pricing) (Basic/free plan), then copy `.env.local.example` to `.env.local` and paste the key in as `TWELVE_DATA_API_KEY`. `.env.local` is gitignored — never commit it.
- **Graceful failure:** if the key is missing/invalid, or a ticker doesn't exist, the profile page shows a plain error message instead of crashing (see `src/app/profile/[symbol]/page.tsx`).

## Company Profile Generator — EODHD (Hong Kong Stock Exchange only)

- **Provider:** [eodhd.com](https://eodhd.com) — brought in specifically because Twelve Data's plan doesn't cover HKEX (confirmed empirically: `/quote` for a real HKEX ticker returns `"available starting with the Pro or Venture plan"`, a $229/mo tier — not worth it for one exchange). EODHD's free tier genuinely does return real HKEX data, also confirmed empirically before writing any code.
- **Free tier limits:** 20 requests/day + a 500-call welcome bonus. Thin — the HK ticker directory (below) is fetched once and cached hard (24 hours) rather than re-fetched per search, to avoid burning through the daily limit.
- **Routing:** entirely symbol-based, no separate exchange parameter — any symbol ending in `.HK` (e.g. `0700.HK`) is routed to EODHD instead of Twelve Data, in `src/app/profile/[symbol]/page.tsx` and `src/app/api/timeseries/route.ts`. `isHongKongSymbol()` in `src/lib/eodhd.ts` is the single source of truth for that check.
- **Endpoints used** (see `src/lib/eodhd.ts`):
  - `/real-time/{code}.HK` — current price, day's change/volume. Cached 60 seconds.
  - `/eod/{code}.HK` — daily closing history (used for the chart, and to *compute* 52-week high/low and average volume — EODHD's real-time endpoint doesn't return either, so this site derives them from real history the same way it already computes 50-day moving average and volatility elsewhere, rather than leaving them blank). Cached 15 minutes. **Correction (2026-07-21):** this endpoint's `limit` parameter does nothing — confirmed empirically that `limit=22` and no `limit` at all return the identical ~1-year default history, with or without `order` set. Bounded correctly using `from`/`to` date-range parameters instead, which do work as documented — this is how the chart's range buttons (1W/1M/3M/1Y/Max) actually narrow the window for Hong Kong tickers.
  - `/exchange-symbol-list/HK` — the full ~3,700-ticker HKEX directory (code, name, type), used to power company-name search and to look up a display name for the quote (EODHD's own company-description data is paywalled on the free tier). Cached 24 hours.
- **Why not use EODHD's or Twelve Data's own search for Hong Kong:** tested both against real company names ("Tencent", "HSBC") before settling on the directory approach — both free-tier search endpoints returned warrants, depositary receipts, and wrong-market noise instead of the actual primary HKEX common-stock listing. The full exchange directory, filtered locally, was the only approach that reliably surfaced the right ticker.
- **Not covered:** fundamentals (EODHD's `/fundamentals` endpoint returns "Only EOD data allowed for free users" on the free tier — same as SEC EDGAR being US-filers-only, HK companies simply show no fundamentals section) and beta (the regression needs Twelve Data's SPY history alongside the target stock's, and Twelve Data has no HK data at all — skipped outright for HK symbols rather than attempting a call guaranteed to fail).
- **Getting a key:** sign up free at [eodhd.com](https://eodhd.com), then add it to `.env.local` as `EODHD_API_KEY`. Every other exchange on this site works with no key here at all — this is purely additive.
- **Graceful failure:** same convention as every other data source on this site — a missing key, invalid ticker, or exhausted daily limit shows a plain "couldn't load" message on the company page (see `src/app/profile/[symbol]/page.tsx`), never a guessed number or a crash.

## Pitch Builder — adds SEC EDGAR (US company fundamentals)

- **Provider:** [SEC EDGAR's XBRL API](https://www.sec.gov/edgar/sec-api-documentation) (`data.sec.gov`) — the official, free source of US public companies' actual filed financial statements. No key or signup at all; the SEC only requires a descriptive `User-Agent` header identifying the app (see `src/lib/secEdgar.ts`), which is not a secret.
- **Coverage:** US-listed companies that file 10-Ks with the SEC only. Non-US tickers (LSE-listed like Shell, AstraZeneca, HSBC, etc.) aren't covered — the Pitch Builder module shows the fundamentals panel only when data comes back, and otherwise just omits it rather than showing broken fields.
- **Endpoints used** (see `src/lib/secEdgar.ts`):
  - `company_tickers.json` — the full ticker → CIK (SEC's internal company ID) lookup table. Cached 24 hours.
  - `xbrl/companyconcept/{cik}/us-gaap/{concept}.json` — one financial-statement line item at a time (e.g. `NetIncomeLoss`, `Assets`), pulled per company from its most recent 10-K, plus prior years' values from the same response (`fetchAnnualConceptHistory()`) so multi-year revenue/net-income history is available without extra requests. We fetch 21 concepts covering revenue, net income, operating income, gross profit, total assets, stockholders' equity, cash, total debt, current assets/liabilities (for working capital), D&A, capex, operating cash flow, dividends paid, buybacks, interest expense, diluted EPS, and basic/diluted weighted-average shares outstanding — rather than the much larger "all facts" endpoint. Operating income, D&A, and diluted EPS keep their full multi-year history (not just the latest value) so EBITDA and EPS growth rates can be computed. Cached 24 hours (annual filings don't change intra-day).
- **Known quirk:** companies don't all use the same XBRL tag for the same concept — e.g. revenue is tagged `RevenueFromContractWithCustomerExcludingAssessedTax` for some filers and `Revenues` for others. `getFundamentals()` tries a short fallback list per concept; if a company uses a tag we haven't listed, that one field just won't show (rather than the whole fetch failing).
- **IFRS filers (2026-07-20 addition):** many foreign-but-US-listed small/mid caps (e.g. Canada Goose) don't file a 10-K under US-GAAP at all — they file a `20-F`/`40-F` under the `ifrs-full` XBRL taxonomy instead, a completely different set of tag names (`Revenue` instead of `Revenues`, `ProfitLoss` instead of `NetIncomeLoss`, etc.) and often report in their home currency rather than USD. `getFundamentals()` now falls back to a modest, spot-checked (not exhaustive) list of IFRS tag names for the most important line items (revenue, net income, gross profit, operating income, assets, equity, cash, current assets/liabilities, D&A, diluted EPS, operating cash flow) — see `IFRS_CONCEPTS` in `src/lib/secEdgar.ts`. Line items too inconsistent to guess reliably across companies (buybacks, dividends, debt breakdown, capex) are simply left unavailable for IFRS filers, same as any other free-data gap.
- **Financial-sector top lines (2026-07-22):** banks and insurers don't tag revenue under the generic concepts — added verified fallbacks (`RevenuesNetOfInterestExpense` for banks/brokers, `PremiumsEarnedNet` for insurers, `InterestAndDividendIncomeOperating` for small lenders), each checked against real filers (Goldman, JPMorgan, Progressive, MetLife, Eagle Bancorp) before shipping. The UI captions revenue with which concept supplied it. Also added a staleness guard: a concept whose newest data is >2 fiscal years old is only used if nothing fresher exists (T. Rowe Price and JPMorgan both carry abandoned tags whose data ends in 2015/2011 — without the guard those could surface as "latest FY").
- **Hong Kong ↔ SEC bridge (2026-07-22):** `src/lib/hkAdrMap.ts` maps 15 verified HK listings to the same legal entity's SEC-filing US ticker (9988.HK↔BABA etc.), so those HK pages show real SEC fundamentals, explicitly labeled. Unsponsored ADRs that never file (Tencent) and HK subsidiaries of US parents are deliberately excluded. Price-based multiples on both sides of each pair are computed from the HK ordinary-share price converted to USD — ADR quotes are per ADS *bundle* (1 BABA ADS = 8 shares) and had been inflating every per-share multiple (BABA P/E showed 204x instead of ~26x, found and fixed 2026-07-22).
- **Bug fix (2026-07-21):** the taxonomy-vs-form pairing above was too rigid — the code assumed "US-GAAP data only ever arrives via a 10-K" and "IFRS data only ever arrives via a 20-F/40-F," and rejected anything that didn't match. That assumption is wrong: which *taxonomy* a foreign private issuer tags under (US-GAAP vs. IFRS) is the filer's own accounting-standard choice, completely independent of which *form* they file. Confirmed empirically on Alibaba (`BABA`): it reports real revenue/net income under the `us-gaap` taxonomy, but files `20-F`/`6-K`, not `10-K` — so it was silently returning zero fundamentals despite the data genuinely existing and being free to fetch. Every US-ADR-linked Chinese/Hong Kong company that reports under US-GAAP while filing as a foreign private issuer (Alibaba, JD.com, Baidu, PDD Holdings, NIO, Trip.com, and others) was affected the same way. Fixed by letting *both* the US-GAAP and IFRS taxonomy lookups accept the full set of forms (`10-K`/`10-K/A` plus `20-F`/`20-F/A`/`40-F`/`40-F/A`/`6-K`/`6-K/A`) — see `US_GAAP_FORMS`/`IFRS_FORMS` in `src/lib/secEdgar.ts`. Verified live: `/profile/BABA` went from "No SEC fundamentals data available" to a full real fundamentals section (revenue, margins, all valuation multiples, credit metrics, growth rates).
- **Formatting bug fix (2026-07-21):** found while verifying the fix above — `formatUSD()` in `src/lib/format.ts` didn't handle negative numbers (its size-bucket checks like `value >= 1e9` are always false for a negative number, so it fell through to a raw `$-20612040200.00` instead of a compact `-$20.6bn`). This affects any company with negative net debt (common for cash-rich companies like Alibaba) or negative free cash flow/net income. Fixed the same way its sibling `formatOriginalCurrency()` already correctly handled it — compare against `Math.abs(value)`, keep the sign separately.
- **Currency conversion (2026-07-20 addition):** when a company's filings come back in a non-USD currency, `getFundamentals()` converts every dollar figure to USD using one current FX rate (see below) before returning it — every downstream calculation (margins, multiples, credit metrics) then works in USD like any other company. The original, pre-conversion figure is preserved as a small "Converted from CAD C$1.2bn"-style caption under the relevant stat, so nothing is silently changed without saying so. This uses one blanket current rate rather than a different historical rate per fiscal year — accurate enough for a student research tool, not meant to be forensically precise.
- **Graceful failure:** if a ticker isn't an SEC filer, or none of the tried concepts (US-GAAP or IFRS) return data, `getFundamentals()` returns `null` and the Pitch Builder simply doesn't render the fundamentals panel for that company.

## Currency conversion — Frankfurter

- **Provider:** [Frankfurter](https://api.frankfurter.dev) (`api.frankfurter.dev`) — a free, no-key currency exchange rate API built on the European Central Bank's published daily reference rates.
- **What it's used for:** converting non-US SEC filers' financial statements (see IFRS note above) from their home currency into USD, via `getExchangeRate()` in `src/lib/fx.ts`.
- **Graceful failure:** if the lookup fails, conversion is skipped (rate of 1) rather than hiding the data — the student sees the raw non-USD number unconverted instead of a blank field.

## Pitch Builder — computed analytics (no new data source, built on the above)

These aren't a data provider — they're our own calculations layered on top of Twelve Data's price history and SEC EDGAR's fundamentals, in keeping with the "analysis, not just data" principle.

- **Beta** (`src/lib/beta.ts`): a real regression, not a looked-up number (Twelve Data's `/statistics` endpoint that would return beta directly is paid-only, see above). Fetches the target symbol's and SPY's 1-year daily closes, aligns them by shared trading date, computes daily returns, then beta = covariance(stock, SPY) ÷ variance(SPY). Returns `null` (shown as "Unavailable") if fewer than 30 shared trading dates are available, so a thin/unreliable regression is never silently presented as a real number.
- **Credit metrics, ROIC, capital allocation** (`src/lib/fundamentalsAnalysis.ts`): pure calculations off SEC EDGAR fundamentals — EBITDA (operating income + D&A, an estimate since EDGAR doesn't tag EBITDA directly), net debt/EBITDA, interest coverage, ROIC (after-tax operating profit ÷ invested capital, assuming a flat 21% tax rate), and a dividends + buybacks summary. Each is `null`-safe: any missing input means that one metric shows "Unavailable" rather than a wrong number.
- **Valuation multiples, growth, and returns** (`src/lib/valuationAnalysis.ts`): market cap (price × shares outstanding — Twelve Data's free tier has no market-cap field), enterprise value, net debt, working capital, free cash flow, and the multiples analysts actually quote (P/E, EV/EBITDA, EV/EBIT, EV/Sales, P/B, FCF yield, dividend yield), plus ROE, ROA, and year-over-year growth in revenue, EBITDA, and EPS. Same `null`-safe convention as the rest of this project — never a guessed number.
- **Peer comps** (`src/lib/comps.ts`, `/api/comps`): there is no free "give me a comps set" endpoint anywhere, so the student types in peer tickers themselves (same as a real analyst choosing a peer set) and the server fetches quote + fundamentals for each, computing P/E, revenue growth, and margins per peer.
- **LBO and M&A calculators** (`src/lib/dealMath.ts`): pure math, not a data source — entry/exit multiples, leverage, and holding period for the LBO; offer price, financing mix, and synergies for the M&A accretion/dilution model. Every assumption is a field the student fills in and can see; the LBO paydown model is a simplified flat percentage rather than a full cash-sweep schedule, and this simplification is documented in the module, not hidden.

## Pitch Builder — Google News RSS (headlines)

- **Provider:** Google News' public RSS search feed (`news.google.com/rss/search`) — free, no key, no signup, same tier of integration as the Wikipedia lookup already used for the company description block (`src/lib/companyInfo.ts`).
- **What it returns:** up to 6 recent headlines for the company name, each with a title, link, publish date, and (parsed out of the title) a source name. Parsed with plain regex rather than an XML library, keeping with this project's "no new dependency unless truly needed" rule.
- **Graceful failure:** if the feed is unreachable or returns nothing, `getCompanyNews()` returns an empty array (never throws), and the News block shows "No recent headlines found for this company." rather than breaking the page.
- **Freshness:** cached 1 hour (`next: { revalidate: 3600 }`) — headlines don't need to be tick-by-tick fresh for a research tool.

## Pitch Builder — "Pro" AI report grading (Anthropic Claude API) — the one paid exception

- **Provider:** [Anthropic's Claude API](https://console.anthropic.com) (`claude-opus-4-6`) — used to grade a student's written report sections (Thesis, SWOT, Bear Case, etc.), checking whether claims are actually supported by the real company data on the page and giving specific, concrete feedback rather than generic praise.
- **This is NOT free**, unlike every other data source on this site. It's the one deliberate exception to the "free and public only" rule (see `docs/DECISIONS.md`) — each grading request costs a small amount on whoever's Anthropic API key is configured.
- **Requires `ANTHROPIC_API_KEY`** in `.env.local` (see `.env.local.example`) — if unset, the feature shows a clear "AI grading isn't configured" message rather than crashing or faking a result. Nothing else on the site is affected by this key being absent.
- **Gated behind an unlock code** (`"bloombruh"`), not real payment — a deliberate, temporary placeholder until there's an actual monetization/access plan (see `docs/DECISIONS.md`). Unlock state is remembered in the browser's `localStorage`; this is a friction gate, not real security.
- **Implementation:** `src/lib/grading.ts` (server-only — reads the API key, sends the student's written blocks + the real company stats to Claude, gets back a structured score/feedback object via the SDK's Zod structured-output support) behind `src/app/api/grade/route.ts` (a thin proxy so the browser never sees the key), triggered from `src/components/pitch/AiGrader.tsx`.

## Central Bank Room — policy rate data (`src/lib/centralBankRates.ts`)

All eight banks' current rate, history, and rate-decision timeline come from real, free, no-key official statistics APIs — each one was tested with a live HTTP call before being wired in, because "documented as free" has burned this project before (see Twelve Data's paywalled `/statistics` endpoint above). Coverage is honestly uneven: not every bank publishes a single, clean, daily policy rate, so lower-quality sources are clearly labelled rather than dressed up as official.

- **Federal Reserve:** [FRED's `fredgraph.csv` export](https://fred.stlouisfed.org/series/DFEDTARU) (series `DFEDTARU`, target rate upper bound). This specific CSV export endpoint needs no API key — FRED's main JSON API does, but this one doesn't. Daily.
- **ECB:** [ECB Statistical Data Warehouse](https://data.ecb.europa.eu/data/datasets/FM) (`FM/D.U2.EUR.4F.KR.DFR.LEV`, deposit facility rate), free, no key. Daily.
- **Bank of England:** [BoE Interactive Statistical Database](https://www.bankofengland.co.uk/boeapps/database/Bank-Rate.asp) CSV export (series `IUDBEDR`, Bank Rate), free, no key. Daily.
- **Bank of Canada:** [Valet API](https://www.bankofcanada.ca/valet/observations/V39079/json) (series `V39079`, target for the overnight rate), free, no key. Daily.
- **Swiss National Bank:** [SNB Data Portal](https://data.snb.ch/en/topics/ziredev#!/cube/zimoma) cube `zimoma`, series `1TGT` (SNB policy rate). Free, no key, but **monthly only** — shown and labelled as monthly, not daily.
- **Reserve Bank of Australia:** [RBA statistics CSV](https://www.rba.gov.au/statistics/cash-rate/) (`f1.1-data.csv`, Cash Rate Target column). Free, no key, but **monthly average, not daily** — same honest "monthly" label as SNB. The RBA's server also blocks requests carrying a generic Node.js or browser User-Agent header (confirmed by testing — even a spoofed Chrome UA gets a 403, while a `curl`-style UA is let through), so this one request sends a `curl`-like User-Agent to get past that filter; this is not bypassing any login or paywall, just matching what a plain command-line request already gets for free.
- **Bank of Japan:** no clean free daily policy-rate series exists, so this uses FRED's `IRSTCI01JPM156N` (the interbank call money rate) as a **proxy** — flagged `isProxy: true` in the code and shown with an on-page disclaimer, since it's not BoJ's own published figure. Monthly.
- **People's Bank of China:** same situation — the PBoC doesn't publish one single daily policy rate, so this uses FRED's `IR3TIB01CNM156N` (3-month interbank rate) as a **proxy**, also flagged and disclaimed on-page. Monthly.
- **Graceful failure:** `getCentralBankRateData()` returns `null` if a live fetch fails for any reason, and the page shows an honest "Rate data is unavailable right now" message rather than a guessed number or a crash.
- **Rate-decision timeline:** derived, not sourced — `src/lib/centralBankRates.ts` walks each bank's history and flags every point where the rate changed. The one-line note next to each move (e.g. "quarter-point hike — moves like this are typically used to cool inflation") is a **generic** description of what that type of move usually does, not the bank's own stated reason for that specific decision (no free source publishes structured rationale per decision) — the page says this explicitly next to the timeline.

## Central Bank Room — Global Overview narrative + per-bank "Economic backdrop" (Anthropic Claude API)

- **Global Overview narrative:** the Global Overview card's "why do rates look like this right now" summary is Claude (`claude-sonnet-4-6`), grounded strictly in the real per-bank hike/cut/hold figures already shown on the card (computed by the new shared `summarizeBankRates()` in `src/lib/centralBankRates.ts`, so the narrative always describes the exact numbers on screen) plus real, period-scoped Google News coverage (`getPeriodNews()`, the same generic date-scoped search built for the Markets Overview module below). Lives in `src/lib/centralBankNarrative.ts` (`explainGlobalRateSituation`), behind `/api/global-rate-narrative` (in-memory cached per period, same "resets on cold start, no database" convention as the other AI narrative routes).
- **Per-bank "Economic backdrop":** a short, simple 2-4 sentence summary of that bank's region's current economic situation, shown before the rate-decision timeline. Also Claude, grounded only in real fetched news about that region's economy (`${region} economy inflation growth jobs`, scoped to the last 3 months) plus the bank's own real current rate and last move. Lives in the same file (`explainRegionalEconomy`) — unlike the global narrative, this is called directly from `src/app/macro/page.tsx`'s server component rather than through an API route, so it owns its own small in-memory cache (keyed by bank id) instead of relying on a route to cache it.
- **Same paid-API exception as the rest of this site's AI features** (AI report grading, rate-decision "Explain more"): requires `ANTHROPIC_API_KEY`; if unset, both sections show a plain "narrative unavailable" fallback rather than crashing or faking a summary — verified live.

## Markets Overview — world situation, equity sectors, private markets

- **Sector/segment price data:** reuses Twelve Data (same provider and free tier as the Company Profile module, see above) — each equity sector and each private-market segment is tracked via a real, liquid, publicly-listed ETF used as a proxy, since there is no free API that publishes a clean "sector return" or, for private markets, an actual fund NAV/return figure. Registries live in `src/lib/marketSectors.ts` (Global Equities/SPY, TMT/XLK, Financial Institutions/XLF, Healthcare/XLV, Energy/XLE, Industrials/XLI, Consumer/XLY) and `src/lib/privateMarketSegments.ts` (Private Equity/PSP, Private Credit/BIZD, Real Estate & Infrastructure/VNQ). Every private-market segment's proxy status is called out explicitly on the page (`PRIVATE_MARKET_PROXY_DISCLAIMER`) — these are real, tradable public securities, not the same thing as an actual private fund's NAV or return.
- **Chart data:** the existing `/api/timeseries` route and `getTimeSeriesForRange()` (`src/lib/marketData.ts`), which gained a new `"1W"` range (7 daily bars) alongside the existing `1D/1M/3M/1Y/MAX` used by the Company Profile chart — purely additive, no existing chart's range buttons changed.
- **News:** Google News RSS (same free, no-key feed used everywhere else on the site), via a new generalized `getPeriodNews(query, daysBack, limit)` in `src/lib/news.ts` — the same date-scoped `after:`/`before:` search pattern already used for rate-decision news, just parameterized so the Markets Overview module can scope any segment's query to whichever period (week/month/year) the reader picked. "Forever" is left unscoped by date, same reasoning as the existing global macro news search.
- **AI-generated narrative:** `src/lib/marketNarrative.ts` (new), same pattern as `src/lib/rateDecisionExplainer.ts` — sends Claude (`claude-sonnet-4-6`) the real computed price return over the period plus the real fetched news articles, and asks for 2-4 grounded sentences on how that segment is doing. Never invents a figure or fact beyond what's handed to it; if there isn't enough real coverage to say something confident, it says so instead of padding. Behind `/api/market-narrative` (thin proxy, in-memory cached per segment+period, same "resets on cold start, no database" convention as `/api/bank-decision-news`), triggered automatically once a reader picks a segment/period (not click-gated, since picking one already is the explicit action). Requires the same optional, paid `ANTHROPIC_API_KEY` as the AI report grader and the rate-decision explainer — if unset, the panel falls back to showing just the real source articles with a plain note, verified live.
- **Commentary:** Adam's own opinion, stored in a plain data file (`src/data/marketCommentary.ts`), same convention as `centralBankOpinions.ts` — starts empty, keyed by segment id (`"world"`, each sector id, each private-market id) so a take can be published for the world situation, one sector, or one private-market segment independently.
- **Homepage teaser:** the same world-situation panel (`WorldSituationOverview.tsx`) renders in a compact form on the landing page, linking through to the full `/markets` module — no separate data source, same live fetch.

## Model Templates — no new data source, one new library

- **Data:** every prefilled number in a downloaded template comes through the exact same code paths as the rest of the site — Twelve Data quotes (EODHD for `.HK`), SEC EDGAR fundamentals (including the HK↔ADR bridge), the computed beta regression, and (for the Market Update sheet) the sector-ETF series and central-bank rate fetchers the Markets Overview and Central Bank Room already use. `src/lib/templates/prefill.ts` is a thin gatherer over those libs, not a new pipeline.
- **Library:** `exceljs` (npm), server-side only behind `/api/template` — generates .xlsx workbooks where every computed cell is a live Excel formula. This is the one genuinely new dependency; chosen because a "model template" that can't recalculate offline is just a picture of a model.
- **In-file attribution:** every workbook carries its own "Data & Sources" sheet (one line per prefilled item, with the generation date) and a guidance sheet stating the conventions — blank blue cells mean no real data existed and nothing was estimated; the two labeled classroom-convention defaults (risk-free/ERP, beta=1.00 fallback) are called out as conventions, not data.

## Central Bank Room — regional index vs. rate ("Markets & the economy")

- **Index data:** each bank's page charts its region's stock index against the policy rate. `src/lib/regionalIndices.ts` maps each bank to a US-listed ETF, all confirmed working on Twelve Data before shipping — SPY (S&P 500) and FEZ (Euro Stoxx 50) track the named index directly; EWU/EWJ/FXI/EWL/EWA/EWC are broad single-country ETFs used as the closest *free* proxy for the UK/Japan/China/Switzerland/Australia/Canada market and are labeled as approximations ("≈ FTSE 100", etc.), never as the exact famous index. ~5 years of daily closes are fetched server-side on the macro page via `getTimeSeries`.
- **Period narrative:** `/api/country-situation` (Claude via `explainCountrySituation`) writes a period-scoped summary of the country's economy and market, grounded strictly in the real index return for the window plus real period-scoped Google News coverage. The prompt is explicitly instructed to stay honest about correlation — never asserting the rate and market move together (or apart) unless the real data supports it. Same optional `ANTHROPIC_API_KEY` and graceful fallback as every other AI feature; cached per bank+period.
- **No correlation claim by the chart:** the overlay just places the two lines on a shared timeline (dual axis) — the on-page caption says so plainly and tells the reader to judge for themselves.

## Explicitly out of scope for now

- Sub-second/tick-by-tick market data — no free source provides this legally; Twelve Data's near-real-time delayed quotes are the ceiling for a free tool.
- Any scraping of Bloomberg, Refinitiv, paid terminals, or content behind paywalls/logins. Never do this.
- NBIM/sovereign wealth fund holdings data — this was the original flagship module's data source; it was dropped along with the SWF Explorer module (see `docs/DECISIONS.md`). Revisit only if Adam decides to bring an NBIM-specific module back later.
