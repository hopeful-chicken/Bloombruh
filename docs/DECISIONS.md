### 2026-07-20 — Added IFRS fundamentals + automatic USD conversion, with a "converted from" caption

**Decision:** Following on from the gap found above, `getFundamentals()` (`src/lib/secEdgar.ts`) now also tries the `ifrs-full` XBRL taxonomy and `20-F`/`40-F` filing forms when a company has no US-GAAP `10-K` data — recovering revenue, net income, gross/operating profit, assets, equity, cash, current assets/liabilities, D&A, diluted EPS, and operating cash flow for foreign-private-issuer filers like Canada Goose. When a company's filings come back in a non-USD currency, every monetary figure is automatically converted to USD (using a new free, no-key FX API — [Frankfurter](https://api.frankfurter.dev), see `src/lib/fx.ts`) before it's used anywhere else in the app, so multiples/margins/credit metrics all just work in USD like any other company. The original figure is preserved and shown as a small caption under the stat, e.g. "Converted from CAD C$1.2bn" (`src/components/Stat.tsx`, `src/lib/format.ts`'s new `formatOriginalCurrency()`).

**Why:** You asked for the USD-converted number to be the headline figure, with the original currency/amount shown as a small note underneath — this keeps every number on the page directly comparable (no mental "wait, is this in CAD or USD?" math) while never hiding that a conversion happened.

**What it means for the project:** One FX rate per company (looked up once, not a different historical rate per fiscal year) is used to convert its whole history — accurate enough for comparing companies at a glance, not meant for penny-precise accounting. A handful of line items that vary too much company-to-company to guess reliably under IFRS (buybacks, dividends, debt breakdown, capex) are simply left unavailable for IFRS filers, same as any other free-data gap already on this site — nothing is ever guessed or silently estimated. Verified against Canada Goose (`GOOS` — now shows real USD-converted fundamentals with CAD captions) and Apple (`AAPL` — completely unaffected, still plain USD, no captions).

### 2026-07-21 — Bug fix: ECB rate data wasn't loading

**Decision:** You reported the ECB page was showing "unavailable." Root cause was a CRLF line-ending bug in `fetchEcb()` (`src/lib/centralBankRates.ts`): the ECB's API returns Windows-style `\r\n` line endings, but the code only split on `\n`, leaving a stray `\r` stuck to the end of the last column name in the header row. Adding `detail=dataonly` to the ECB request trims each row to just the columns actually used, shrinking the same 15 years of data to ~350KB — but this also moved `OBS_VALUE` to the very last column, which is what turned the previously-silent `\r` bug into an actual failure (the header lookup missed it entirely, so the whole fetch quietly returned no data). Fixed the line-splitting to `/\r?\n/`, matching the pattern already used correctly by the other bank fetchers (`fetchBoe`, `fetchSnb`, `fetchRba`) — `fetchEcb` was the one holdout still using a bare `\n` split.

**Why:** A genuine bug report — the ECB is one of the two flagship rate series (alongside the Fed) so this needed a real fix, not a workaround.

**What it means for the project:** No behavior or feature change — same data, same layout — just a smaller, faster, more reliable fetch for the ECB specifically. Verified by tracing the exact failure with temporary debug logging (confirmed `header.indexOf("OBS_VALUE")` was returning `-1` due to the trailing `\r`), fixing it, removing the debug logging, then reloading `/macro?bank=ecb` live several times and confirming the 2.25% deposit facility rate, full history chart, and rate-decision timeline all render correctly and quickly (fetch now well under the 2MB cache limit, so repeat loads are cache-hits in well under 200ms). `tsc --noEmit` passes clean.

**A real, unrelated bug found and fixed while investigating:** the title slide's "LONG"/"SHORT" badge used `slide.addShape("rect", { rectRadius: ... })` — the pptxgenjs skill's own documentation warns `rectRadius` only has an effect on a `roundRect` shape, not a plain `rect`. Fixed to `roundRect` and all 9 decks regenerated. Still no LibreOffice/`pdftoppm` on this machine to visually confirm the fix by eye — disclosed rather than glossed over.

**What it means for the project:** new `src/lib/pitchUnlock.ts` (single source of truth for the unlock code, storage key, and the template-id allowlist — both `PitchToolkitGate.tsx` and the new API route import from it instead of each hardcoding their own copy); new `src/app/api/pitch-template/route.ts`; `src/data/pitch-templates/*.pptx` (moved from `public/downloads/pitch-templates/`, which no longer exists); all 9 toolkit download links in `src/data/analysis.ts` updated to the new `/api/pitch-template?id=...&code=...` URLs. ### 2026-08-05 — Fixed, properly this time: locked pitch content was shipped to every visitor regardless of the lock
